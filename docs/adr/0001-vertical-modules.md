# ADR-0001: Вертикально-модульная архитектура для портфолио

## Статус

Принято.

## Контекст

Проект стартует с нуля, но должен сразу поддерживать:

- публичный frontend;
- административную панель;
- backend API;
- импорт и экспорт контента;
- локализацию;
- темы;
- доступность;
- безопасное расширение без переписывания базовой структуры.

Если построить проект только по техническим слоям, то компоненты `projects`, `profile`, `themes` и `localization` быстро начнут смешиваться.

## Решение

Каждый функциональный компонент оформляется как отдельный vertical slice.

Frontend-модуль содержит:

- `api/`;
- `business/`;
- `types/`;
- `ui/`;
- `errors/`;
- `tests/`.

Backend-модуль содержит:

- `api/`;
- `application/`;
- `domain/`;
- `infrastructure/`;
- `cache/`;
- `tests/`.

Общие зависимости выносятся только в `packages/` и используются через явные публичные интерфейсы.

## Последствия

Плюсы:

- проще развивать компоненты независимо;
- легче переносить логику между публичной частью и админкой;
- ниже риск сползания в хаотичный shared-code;
- проще внедрять импорт/экспорт и кеширование по модулям.

Минусы:

- стартовая структура кажется более объёмной;
- нужен строгий контроль импортов и границ модулей;
- часть шаблонного кода появляется раньше, чем в MVP-подходе.
